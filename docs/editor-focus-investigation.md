# 发布后编辑框短暂无法输入调查

## 现象

在 Electron 客户端中发布或保存节点后，标题和内容框可以被点击并获得焦点，但短时间内键盘输入不产生文本；稍后输入能力会自行恢复。

## 现场证据

- 输入框的 `disabled` 和 `readOnly` 均为 `false`。
- 输入框可见，`pointer-events` 为 `auto`。
- `elementFromPoint` 命中实际输入框，不存在覆盖点击的元素。
- 鼠标点击能触发 `focusin`，`document.activeElement` 指向正确输入框。
- 异常期间部分字母键产生 `keydown` 和 `keyup`，但没有 `beforeinput` 或 `input`。
- CDP 的 `Input.insertText` 可以直接写入文本。
- 等待一段时间后，普通键盘输入自行恢复。

这些结果排除了输入框被永久禁用、只读、隐藏或被覆盖的情况。

## 根因判断

成功提交后，旧实现立即调用同步 `alert()`，同时异步启动节点列表刷新但不等待完成。Electron 的模态弹窗、页面重渲染和输入法状态在同一时间交错，导致渲染完成后输入框虽然已经获得焦点，文本输入状态仍可能短暂异常。

## 修复

- 移除添加和修改成功后的同步提示弹窗。
- `addNode()` 和 `updateNode()` 等待 `getNode()` 完成后再刷新列表和地图。
- 提交流程结束时统一恢复按钮及输入框状态，并在下一帧聚焦标题框。
- 桌面端 preload 对尚未更新的远程页面忽略“添加节点成功”和“修改成功”两个旧成功提示。
- 保留编辑区交互保护，防止特殊节点注入的样式改变输入框可见性和可点击性。

## 回归路径

1. 在标题和内容框输入文本。
2. 发布新节点或保存修改。
3. 列表刷新后立即点击输入框并输入，不等待额外时间。
4. 刷新页面，再次点击标题和内容框并输入。
5. 确认特殊节点仍位于节点卡片内，显式 `<!-- fullscreen -->` 的节点除外。
